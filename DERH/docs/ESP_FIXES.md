# Как чинился ESP: разбор всех багов

Хронология с причинами. Смысл документа не в том, что было исправлено, а в
том **как искалась причина** — чтобы следующий баг не пришлось разбирать
теми же двумя днями.

---

## Главный вывод

Почти каждый баг ESP оказывался не там, где выглядел.

| Симптом | Где искали | Где оказалось |
|---|---|---|
| Боксы над игроками | Вертикальный оффсет | Оффсет калиброван под ДРУГУЮ проекцию |
| ESP плавает за камерой | Камера | Владельцем камеры был ЧУЖОЙ игрок |
| Прицел выше цели | Точка прицеливания | Углы считались от другой точки, чем проекция |
| Скелет не рисуется | Логика скелета | Не разыменована обёртка, KCC не находился |
| Фона нет | Загрузка текстуры | Загрузчик остался в отключённой функции |

**Правило, выведенное из этого:** прежде чем чинить — доказать причину
логом или расчётом. Три раза правка «по симптому» создавала новый баг.

---

## Баг 1. Античит убивал игру через 90 секунд

**Симптом.** Игра стабильно падала примерно через полторы минуты после
запуска чита.

**Причина.** CatsBit следит за **объёмом** обращений к памяти процесса.
Сканы анонимных областей (~200 МБ на проход) он засекал.

**Решение.** Убраны все сканы анонимной памяти. Точечные чтения внутри
маппингов libil2cpp безопасны — их объём на порядки меньше.

**Правило на будущее:** любой новый обход коллекции обязан иметь потолок и
выполняться не каждый кадр. Пример — обход `NetworkClient.spawned`: лимит
1500 объектов, раз в 30 кадров, одним `vm_readv` на блок словаря.

---

## Баг 2. Резолв классов: две функции-двойника

**Симптом.** ESP не работал совсем, `klass+0x10` вместо имени класса
содержал байты `fe 4f bf a9`.

**Разбор.** Эти байты — `stp x30, x19, [sp, #-0x10]!`, то есть **пролог
функции**. Значит указатель вёл в `.text`, а не на `Il2CppClass`. Мы читали
таблицу МЕТОДОВ вместо таблицы КЛАССОВ.

В libil2cpp есть две функции почти одинаковой формы:

```
GetMethodInfoFromMethodDefinitionIndex   делит на header[0xcc] / [0xd0]
Class::FromTypeDefinition                делит на header[0xe4] / [0xe8]
```

Обе: XOR-ключ, `sdiv`, индексированная загрузка, запись в кэш. Различаются
**только полем заголовка, на которое делят**.

**Решение.** `s_TypeInfoDefinitionTable` = `Il2CppClass**`, индексируется
по TypeDefinitionIndex. Мнемоника: **`= ctx global + 0x48`**.

**Проверка на устройстве:** разыменуй `klass + 0x10`. Строка = таблица
классов. Код = таблица методов, адрес неверен.

---

## Баг 3. Позиция бралась из серверного тика

**Симптом.** Бокс отставал от бегущего игрока на полметра-метр.

**Причина.** `PM.lastTickPosition (0x1C8)` — серверный тик, 10-20 Гц. Модель
между тиками движется интерполированно, а мы рисовали по последнему тику.

**Решение.** Брать то, чем игра РИСУЕТ:

```
KCC.head (0x88)                                голова, интерполированный Transform
KCC.Motor(0x68).LastInterpolatedPosition(0x1EC) ноги этого кадра
Motor.CapsuleHeight (0x34)                     живая высота (и признак приседа)
Motor.BaseVelocity (0x210)                     скорость для упреждения
```

**Побочный выигрыш:** вертикальный оффсет стал не нужен — габариты бокса
теперь фактические, от ног до головы.

---

## Баг 4. InterfaceReference — обёртка, а не объект

**Симптом.** `stage=2` в диагностике: KCC не находится.

**Причина.** `PM.kccReference (0xB0)` имеет тип `InterfaceReference<sA>` —
это **managed-объект-обёртка**, а не сам KCC. В дампе её поле `_component`
значится на `+0x0`, но это смещение внутри блока данных: у managed-объекта
первые `0x10` байт занимает заголовок (klass + monitor).

**Первая попытка** — читать `+0x10`. Не сработало, раскладка оказалась иной.

**Решение — перестать угадывать.** У KCC поле `player (0x78)` указывает
**обратно на исходный PM**:

```cpp
auto isRealKcc = [&](uint64_t cand) {
    return ox_isPtr(cand) && rpm<uint64_t>(cand + ox::KCC_PLAYER) == player;
};
// перебираем первые 0x40 байт обёртки, берём того, у кого сошлось
```

Случайным такое совпадение быть не может.

**Правило:** если смещение поля внутри чужой структуры неизвестно — ищи
**обратную ссылку** и проверяй ею, вместо подбора константы.

## Баг 5. Матрица камеры и оффсет, откалиброванный под другое

**Симптом.** После включения матричного W2S боксы встали ровно на высоту
роста НИЖЕ игроков.

**Разбор — чистая арифметика из лога.** В логе `pos=(-31.96, 10.38, 24.65)`,
все игроки на y=10.38, то есть это позиция ног. Константы: `BOX_FOOT=0`,
`BOX_HEAD=1.85`, `espBoxYOffset=-1.84`.

```
низ бокса  = 10.38 - 1.84 + 0    = 8.54
верх бокса = 10.38 - 1.84 + 1.85 = 10.39
игрок занимает 10.38 .. 12.23
```

Бокс целиком под игроком, ровно на рост ниже.

**Причина.** `-1.84` подбирался под УГЛОВУЮ проекцию, которая сама вносила
вертикальный сдвиг. Матрица геометрически верна — и оффсет стал чистым
смещением вниз.

**Решение.** При активной матрице оффсет принудительно 0:

```cpp
static inline float ox_boxYOffset() {
    return g_camVPValid ? 0.0f : espBoxYOffset;
}
```

**Правило:** подобранная руками константа привязана к тому пути, под который
подбиралась. Меняешь путь — константа теряет смысл.

---

## Баг 6. Прицел выше цели

**Симптом.** Аим с выбранным «body» целился на две головы выше.

**Причина.** Цель ВЫБИРАЛАСЬ матричной проекцией, а углы доворота считались
от `cam.pos` — реконструированной позиции из `worldCameraRoot`. Две разные
точки отсчёта, разница по вертикали и есть сдвиг прицела.

**Решение.** Достать позицию камеры из самой view-матрицы. Для
ортонормированной `V = [R | t]`, где `t = -R·eye`:

```
eye = -Rᵀ·t
```

**Правило:** выбор цели, расчёт углов и LOS-луч обязаны идти от ОДНОЙ точки.

## Баг 7. Присед, объявленный нечитаемым

**История.** Сначала я заявил, что присед внешнему читу недоступен: в
`PlayerFlags` бита нет, а `Animator.GetBool` требует вызова в процессе игры.
Выкатил ручной тоггл «Crouch-safe».

**Это была ошибка.** Признак есть, просто **геометрический**: игра уменьшает
`Motor.CapsuleHeight (0x34)` с `KCC.normalHeight (0xA0)` до
`KCC.m_CrouchHeight (0xA4)`.

**Решение.** Точка прицела — доля от ЖИВОЙ высоты:

```cpp
float H = anchorHead.y - anchorFeet.y;   // фактическая высота ЭТОГО кадра
head 0.97   neck 0.86   body 0.68
```

Игрок присел → голова опустилась → H уменьшилась → прицел уехал вниз сам.

**Правило:** «признака нет» ≠ «нет флага с таким именем». Ищи следствие в
геометрии.

## Баг 8. Карусель сбросов локального игрока

**Симптом.** ESP плавало с начала матча, в логе `viewOff=-1` всё время —
поиск матрицы не отрабатывал ни разу.

**Разбор.** В логе 97 сбросов локального PM за катку, из них 91 с
`frozen=1`, `cands=8`.

`cands=8` — это потолок массива (`nc < 8`), а не реальное число кандидатов.
`ox_localPlayerAlive` проверяла лишь наличие MouseLook + RaycastManager, а
они есть у ВСЕХ игроков. Значит `nc > 1` истинно всегда, и условие сброса
`frozen && nc > 1` срабатывало, стоило замереть на пару секунд.

**Сцепка:** каждый сброс обнулял `g_camViewMatOff`. Поиск матрицы стартовал
и на следующем кадре стирался — до применения не доживал.

**Решение.** Кэш матрицы привязан к КАМЕРЕ, а не к игроку. `frozen` убран
из условия сброса.

**Правило:** не привязывай кэш к значению, стабильность которого не
подтверждена логом.

## Баг 9. Корень плавания — чужой игрок как «свой»

**Симптом.** ESP плавало даже после всех фиксов выше.

**Причина.** Все критерии «кто локальный» были эвристиками:

| Критерий | Почему промахивался |
|---|---|
| MouseLook + RaycastManager | Есть у каждого игрока |
| Замороженные углы | Живой, не трогающий экран, = труп |
| Transform над ногами | Верно для всех живых |

Владельцем камеры мог стать чужой PM. Тогда базис строился из ЧУЖИХ углов:
свою камеру поворачиваешь, боксы считаются от чужой — плывут. И «само
чинилось», пока тот игрок стоял неподвижно.

**Решение — прямой флаг Mirror:**

```
PlayerManager : Mirror.NetworkBehaviour
NetworkBehaviour.netIdentity   0x40
NetworkIdentity.isLocalPlayer  0x4A
```

Mirror выставляет его **ровно одному объекту за матч**.

Попутно: массив кандидатов был на 8 при 12-13 игроках — свой PM мог
оказаться девятым. Расширен до 16, флаг ищется по всему списку.

**Правило:** прежде чем строить эвристику, поищи прямой ответ в дампе.

## Баг 10. Отрисовка по устаревшим экранным координатам

**Симптом.** После смерти боксы оставались на экране и ехали вместе с
поворотом камеры, не уходя за край.

**Причина.**

```cpp
if (liveCam.valid) { ...считаем W2S... }
else { w2sBottom = player.w2sBottom; }   // ← вот оно
```

При смерти гасился `liveCam.valid`, и цикл брал ЭКРАННЫЕ координаты
прошлого кадра. Они статичны — отсюда «приклеенность».

**Три дополнительных пути к тому же:**

1. Гистерезис на 8 промахов = ~130 мс по протухшей матрице. Ужат до 2.
2. Камера трупа отдаёт геометрически ВАЛИДНУЮ, но застывшую матрицу.
   Ловится сравнением содержимого между кадрами: не менялась дольше
   секунды — мертва.
3. Смерть гасила только угловой путь, а блок чтения матрицы шёл ПОСЛЕ и
   тут же ставил флаг обратно.

**Решение.** Нет живого источника проекции — `continue`, не рисуем ничего.

**Правило:** пустой экран честнее устаревших данных. Приклеенные боксы не
просто бесполезны — они показывают врагов не там, где те есть.

## Баг 11. Загрузчик текстур в отключённой функции

**Симптом.** После перехода на новое меню пропали фон, иконки и фигура
превью.

**Причина.** `oxLoadIcons()` вызывался изнутри `Layout_tick_UI`, которую я
отключил при переходе на `ui_v3`. Ни одна текстура не грузилась, все
`ImTextureID` оставались нулями, а код молча пропускал отрисовку через
`if (g_texMenuArt)`.

**Подтверждение объективное:** бинарник вырос с 3.38 до 3.72 МБ — линкер
раньше выкидывал ассеты как недостижимые.

**Правило:** переносишь точку входа — проверь, что ещё на ней висело.
Молчаливые `if (ptr)` прячут такие поломки.

## Что осталось нерешённым

| Функция | Причина | Можно ли добить |
|---|---|---|
| Валл-чек | `saveList` наполняется только на СЕРВЕРЕ (`OnStartServer`), у клиента пуст by design | Резерв через `NetworkClient.spawned` даёт единицы объектов из ~50. Нужен другой источник геометрии |
| Скрытие тимейтов | Три источника состава пусты: `nWc.team`=0, `TeammateStates` пуст, UI-панель тоже | Похоже, состав команды хранится где-то ещё. Искать по дампу заново |
| Скелет | `KCC.head` отдаёт указатель, но трансформ не читается | Проверить `OBJ_CACHED_PTR` и `TR_INT_MATRIXPTR` — возможно, у этих Transform иная раскладка |
