# Диагностика: от симптома к причине

Как читать лог и что делать с каждым симптомом.

---

## Включить диагностику

По умолчанию логирование **вырезано компилятором** — ни файла на sdcard, ни
строк в бинарнике. Для отладки собирай так:

```bash
ndk-build -j8 \
  NDK_PROJECT_PATH=$(pwd) \
  APP_BUILD_SCRIPT=$(pwd)/Android.mk \
  NDK_APPLICATION_MK=$(pwd)/Application.mk \
  APP_CFLAGS=-DOX_ENABLE_LOG
```

Лог пишется в `/sdcard/Download/eclips_oxide_<дата>.log` и дублируется в
logcat (`adb logcat -s EclipsOxide`).

**Не оставляй такую сборку для игры:** на каждую строку идут три синхронные
операции — `fflush(stdout)`, `__android_log_write` и запись на sdcard.

---

## Главная строка лога

Печатается раз в 2 секунды:

```
[w2s] matrix=1 cam=1 dead=0 isLocal=1 | viewOff=112 projOff=176 | pm=0x7a... nativeCam=0x7b... | anchors=7/9
```

| Поле | Что значит | Норма |
|---|---|---|
| `matrix` | Работает матричный W2S | 1 |
| `cam` | Валиден угловой базис | 1 |
| `dead` | Локальный игрок мёртв/респавнится | 0 |
| `isLocal` | Владелец камеры — точно мы | **1** |
| `viewOff` / `projOff` | Найденные смещения матриц | не -1 и не -2 |
| `nativeCam` | Указатель нативной камеры | не 0 |
| `anchors` | Сколько целей с якорями модели | близко к общему |

**Читай слева направо.** Первое поле не в норме — причина в нём, остальные
следствия.

## Симптомы

### ESP плавает / едет за поворотом камеры

```
[w2s] matrix=1 cam=1 dead=0 isLocal=0
                                    ^^^ вот причина
```

`isLocal=0` — владельцем камеры выбран **чужой** игрок. Базис строится из
его углов: свою камеру поворачиваешь, боксы считаются от чужой.

`isLocal=-1` — `netIdentity` не читается. Проверь `NB_NET_IDENTITY (0x40)`
и `NI_IS_LOCAL_PLAYER (0x4A)` в свежем `il2cpp.h`.

Полная история этого бага — в `ESP_FIXES.md`, баг 9.

---

### ESP остаётся на экране после смерти

```
[w2s] matrix=1 cam=0 dead=1
```

Так и должно быть: при `dead=1` ESP **намеренно скрыт** до появления новой
камеры. Пустой экран честнее приклеенных боксов.

Если боксы всё же висят при `dead=1` — где-то остался путь, берущий
экранные координаты из кэша. Ищи `player.w2sBottom` в цикле отрисовки.

Ещё маркер:

```
[cam] матрица не менялась 1.4с — камера мертва, ESP скрыт
```

Значит поймали застывшую камеру трупа. Она отдаёт геометрически валидную
матрицу, которая просто больше не обновляется.

---

### Боксы выше или ниже игроков

Посчитай по логу, не подбирай на глаз:

```
pos=(-31.96, 10.38, 24.65)     это позиция НОГ (lastTickPosition)
низ бокса  = pos.y + ox_boxYOffset() + BOX_FOOT
верх бокса = pos.y + ox_boxYOffset() + BOX_HEAD
```

При `matrix=1` оффсет обязан быть 0. Если бокс уехал ровно на высоту роста
(1.84 м) — где-то применяется `espBoxYOffset` напрямую, минуя
`ox_boxYOffset()`.

При `anchors=N/N` габариты берутся от модели, и оффсет не участвует вообще.

### Матрица не находится

```
[w2s] matrix=0 viewOff=-1     поиск НЕ ЗАПУСКАЛСЯ
[w2s] matrix=0 viewOff=-2     искали и не нашли
[w2s] ... nativeCam=0x0       до объекта камеры не дошли
```

`-1` при `nativeCam=0` — рвётся цепочка
`PM.raycastManager(0x88) → RaycastManager.m_WorldCamera(0x30) → Camera →
m_CachedPtr(0x10)`. Сверь смещения с `il2cpp.h`.

`-2` — подпись не совпала. Матрицы ищутся в окне `0x600` с шагом 4 по
критериям:

```
view: последняя строка (0,0,0,1), базисные столбцы единичные
      и взаимно перпендикулярны, трансляция ненулевая
proj: m23 == -1, m33 == 0, диагональ в 0.15..12,
      восемь позиций строго нулевые
```

Расширь окно в `ox_findCameraMatrices` до `0xC00`. Если не помогло —
ослабь допуски ортонормальности с `2e-3` до `1e-2`.

Успешный поиск выглядит так:

```
[cammat] view-матрица найдена @+0x70  t=(31.78 -15.16 18.66)
[cammat] proj-матрица найдена @+0xB0  m00=0.9319 m11=2.0710
```

Проверка на вменяемость: `m11/m00` должно равняться соотношению сторон
экрана. Для 2400x1080 это 2.222.

### Якоря модели не читаются

```
[anchor] pm=0x7a.. ref=0x7a.. kcc=0x0 stage=2 headTr=0x0 cap=0.00
```

Поле `stage` показывает, на каком шаге оборвалась цепочка:

| stage | Что не вышло | Куда смотреть |
|---|---|---|
| 1 | Нет `PM.kccReference` | `PM_KCC_REFERENCE (0xB0)` |
| 2 | KCC не найден в обёртке | `KCC_PLAYER (0x78)` — обратная ссылка |
| 3 | Трансформ головы не читается | `KCC_HEAD (0x88)`, `OBJ_CACHED_PTR`, `TR_INT_MATRIXPTR` |
| 4 | Нет позиции ног | `MOTOR_INTERP_POS (0x1EC)` |
| 5 | Геометрия не прошла санити | Смотри `dy` и `dxz` в той же строке |

При `stage=5` проверь `dy`: он должен быть 0.40..2.60 (рост человека). Если
`dy` огромный или отрицательный — читается мусор, цепочка ведёт не туда.

---

### Игра падает примерно через 90 секунд

Античит CatsBit засёк **объём** обращений к памяти. Ищи недавно добавленный
скан коллекции без потолка.

Безопасно: точечные чтения внутри маппингов libil2cpp.
Опасно: обходы анонимной памяти, циклы без ограничения размера.

Образец правильного обхода — `NetworkClient.spawned`: лимит 1500 объектов,
раз в 30 кадров, один `vm_readv` на весь блок словаря.

### Резолв классов не проходит

```
klass не похож на указатель — RVA либо база неверны
```

**Проверка на устройстве.** Разыменуй `klass + 0x10`:

- строка (`"PlayerManager"`) — таблица классов, всё верно
- код (байты вроде `fe 4f bf a9` = `stp x30, x19, ...`) — это таблица
  **методов**, адрес неверен

Правильная таблица — `s_TypeInfoDefinitionTable`, мнемоника
**`= ctx global + 0x48`**.

Подробности про две функции-двойника — в `ESP_FIXES.md`, баг 2.

---

### Тимейты не скрываются

```
[team] lw=0x7a.. lpf=0x0 roster=-1 | states=0x0 cnt=-1 online=-1 | tid='3200...'
```

`lpf=0x0` при живом `lw` — компонент команды есть, а данные пусты.

Проверены три источника, все пустые в текущем билде:

1. `nWc.team (0x90)` → приходит нулём
2. `nWc.TeammateStates (0x70)` → словарь пуст
3. `RaycastManager.teamManager(0x28) → CW.membersList(0x90)` → тоже

`tid` при этом читается нормально — значит сверять есть с чем, не хватает
самого состава. Тоггл убран из меню до выяснения.

### Меню: рубленые углы

Два подводных камня ImGui, оба уже закрыты — но если появятся снова:

**1. `AddRectFilledMultiColor` не принимает радиус.** Всегда рисует острый
прямоугольник. Наложенный на скруглённую подложку, торчит углами.

Решение — красить вершины скруглённого пути:

```cpp
int v0 = dl->VtxBuffer.Size;
dl->PathRect(a, b, r);
dl->PathFillConvex(IM_COL32_WHITE);
// пройти по вершинам от v0 и присвоить цвет по позиции
```

**2. Окно клипует drawlist по своим границам.** Ореол рисуется наружу и
обрезается ровно по краю панели. Окно должно быть шире области отрисовки на
величину свечения (`BLEED = MM(3.6f)`).

**3. Фиксированное число сегментов дуги.** При радиусе 42 px и 14 сегментах
грань получается 4.7 px — видно фаски. Считай от радиуса, шаг ~1.5 px.

## Быстрые проверки

```bash
# Диагностические строки в релизной сборке (должно быть 0)
for p in "\[w2s\]" "\[anchor\]" "\[team\]" "\[skel\]"; do
  echo -n "$p: "; strings libs/arm64-v8a/eclipsoxide | grep -c "$p"
done

# Ассеты попали в бинарник?
ls -la libs/arm64-v8a/eclipsoxide     # релиз ~3.7 МБ; 3.38 = ассеты выпали

# Дамп не мусор?
grep -c "^public class" dump.cs        # ожидаем ~7000
```
