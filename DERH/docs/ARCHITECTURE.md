## Поток кадра

```
main loop
 ├─ Layout_tick_UI()  ──►  OxDrawUiV3()          интерфейс
 │
 ├─ UpdatePlayerCache()                          раз в g_cacheInterval кадров
 │   ├─ ox_getCamera()      выбрать локального игрока
 │   ├─ ox_readHP()         отсев мёртвых
 │   ├─ ox_readNickname() / ox_readWeaponName() / ox_readArmor()
 │   └─ ox_readPlayerFlags()
 │
 └─ если espdraw || aimm:                        КАЖДЫЙ кадр
     ├─ ox_buildCameraFromPlayer()   угловой базис
     ├─ ox_getNativeCamera() + ox_readViewProjection()   VP-матрица
     ├─ для каждого игрока:
     │   ├─ ox_readPos()             свежая позиция
     │   ├─ ox_readModelAnchors()    голова/ноги из модели
     │   ├─ project()                матрица либо углы
     │   └─ отрисовка бокса, HP, подписей
     ├─ ox_runAimbot()
     └─ ox_drawRadar()
```

**Разделение дорогого и дешёвого.** Тяжёлый скан (поиск игроков, HP, ники,
оружие) идёт раз в несколько кадров. Позиции и проекция — каждый кадр,
иначе боксы отстают от бегущей цели.

## Резолв классов

```
libil2cpp base
  + OX_S_TYPEINFO_TABLE_RVA  ──►  Il2CppClass**  (s_TypeInfoDefinitionTable)
      [TypeDefIndex]         ──►  Il2CppClass*
        + 0x10 name          ──►  const char*    проверка имени
        + 0xB8 static_fields ──►  статики класса
```

Индексация по TypeDefIndex, а не по захардкоженному TypeInfo RVA. TDI при
обновлениях меняется редко, а RVA — каждый раз.

Имя класса **сверяется по содержимому** (`ox_asciiEquals`), не по указателю:
указатель может вести в `.rodata` libil2cpp и совпадать случайно.

Мнемоника расположения таблицы: **`= ctx global + 0x48`**.

## Геометрия ESP

Два источника, второй — запасной:

```
ЯКОРЯ МОДЕЛИ (основной, то что игра РИСУЕТ)
  PM.kccReference(0xB0) ──► обёртка InterfaceReference
    перебор первых 0x40 байт, проверка KCC.player(0x78) == PM
      KCC.head(0x88)                          ──► голова
      KCC.Motor(0x68).LastInterpolatedPosition(0x1EC) ──► ноги
      Motor.CapsuleHeight(0x34)               ──► живая высота = признак приседа
      Motor.BaseVelocity(0x210)               ──► скорость для упреждения

СЕРВЕРНЫЙ ТИК (запасной)
  PM.lastTickPosition(0x1C8) + espBoxYOffset
```

Тик обновляется 10-20 Гц, поэтому на бегущей цели бокс отстаёт. Якоря
интерполированы и обновляются каждый кадр.

## Проекция

```
МАТРИЧНАЯ (основная)
  PM.raycastManager(0x88) ──► RaycastManager.m_WorldCamera(0x30)
    ──► Camera.m_CachedPtr(0x10) ──► нативный объект
        поиск view/proj по подписи, один раз за сессию
        VP = proj * view
        позиция камеры = -Rᵀ·t из view-матрицы

УГЛОВАЯ (запасная)
  MouseLook.kqP.x / .y ──► базис из тригонометрии
  FPManager.kYl - kSP  ──► живой вертикальный FOV
```

Через один и тот же проектор идут **все** пути отрисовки: бокс, скелет,
3D-бокс, точка прицеливания. Если бы один остался на углах, он разъехался
бы с остальными.

Нет живого источника — не рисуем ничего. Устаревшие экранные координаты
приклеиваются к экрану и едут вместе с поворотом.

## Интерфейс

Размеры выведены из физики устройства, а не подобраны:

```
2400x1080, ~6.7", 395 ppi  ──►  1 мм = 15.5 px

палец:  минимум 7 мм, комфорт 9 мм, подушечка большого 11 мм
дуга большого пальца 75 мм = 1162 px от нижнего угла
  ──► в ландшафте центр экрана достаётся только указательным
```

Всё в коде идёт через `MM()`, поэтому физический размер сохраняется на любом
экране.

**Высота панели выведена из строки**, а не задана процентом: шапка 8 мм +
ровно 5 строк по 8 мм. При произвольном проценте снизу остаётся мёртвая
полоса — это было видно на пробном рендере раскладки.

Контролы в две колонки: по вертикали помещается 5 строк, по горизонтали
места вдвое больше нужного.

### Стекло

Настоящего backdrop-blur в ImGui нет — кадр под окном недоступен. Материал
собирается слоями, каждый за свой эффект:

```
1. затемнение сцены        стекло гасит то, что за ним
2. холодная подложка       у стекла свой оттенок, не чёрный
3. фоновый арт             анимированный дрейф UV
4. свет сверху             градиент по скруглённой форме
5. цветная дымка           подсветка проникает внутрь
6. плёнка зерна            матовость
7. кромка преломления      яркая линия сверху-слева
8. внешний ореол           свечение наружу, дышит
```

Все цветные слои читают один акцент — ползунок подсветки меняет весь
материал разом.

## Логирование

Вырезано компилятором. Макросы разворачиваются в
`do { (void)sizeof(...); } while(0)`: `sizeof` не вычисляет выражение,
поэтому аргументы не исполняются, а строки форматов исчезают из бинарника.

Диагностические блоки обёрнуты в `#ifdef OX_ENABLE_LOG` **целиком** — внутри
них были настоящие чтения памяти игры, которые макрос бы не убрал.

Собрать с логом: `APP_CFLAGS=-DOX_ENABLE_LOG`.

## Ограничения античита

CatsBit следит за **объёмом** обращений к памяти процесса.

Безопасно: точечные чтения внутри маппингов libil2cpp.
Опасно: сканы анонимной памяти, обходы коллекций без потолка.

Образец правильного обхода — `NetworkClient.spawned`: лимит 1500 объектов,
раз в 30 кадров, один `vm_readv` на весь блок словаря вместо чтения по
элементу.
