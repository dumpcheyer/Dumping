## Восстановление Font.h

Весит 6.89 МБ и не проходит через GitHub Contents API (лимит 4 МБ на тело
запроса). Лежит рядом как `Font.h.gz.b64`.

```bash
cd include/ImGui/font
base64 -d Font.h.gz.b64 | gunzip > Font.h
md5sum Font.h   # 7c667be5b679273f9f4a0424c75d7261
rm Font.h.gz.b64
```

Без этого сборка упадёт на отсутствующем `OPPOSans_H`.

## Сборка

```bash
ndk-build -j8 \
  NDK_PROJECT_PATH=$(pwd) \
  APP_BUILD_SCRIPT=$(pwd)/Android.mk \
  NDK_APPLICATION_MK=$(pwd)/Application.mk
```

Результат: `libs/arm64-v8a/eclipsoxide` (~3.7 МБ), standalone PIE, под `su`.

**С диагностикой:** добавить `APP_CFLAGS=-DOX_ENABLE_LOG`. Без этого флага
логирование вырезано на этапе компиляции — ни файла на sdcard, ни строк в
бинарнике.

Если распаковывали NDK через `unzip` или Python `zipfile` — симлинки в
тулчейне превращаются в текстовые файлы и `clang` не находится. Восстанавливать
по флагу `S_ISLNK` в `external_attr`.

## Определение локального игрока

Единственный надёжный признак — прямой флаг Mirror:

```
PlayerManager : Mirror.NetworkBehaviour
NetworkBehaviour.netIdentity    0x40
NetworkIdentity.isLocalPlayer   0x4A
```

Mirror выставляет его ровно одному объекту за матч.

Все прежние критерии были эвристиками и промахивались:

| Критерий | Почему не работает |
|---|---|
| Наличие MouseLook + RaycastManager | Есть у КАЖДОГО игрока |
| Замороженные углы взгляда | Живой игрок, не трогающий экран, неотличим от трупа |
| Transform над ногами | Верно для всех живых, не только для нас |

Когда владельцем камеры становился чужой PM, базис строился из чужих углов:
свою камеру поворачиваешь, а боксы считаются от чужой — ESP «плавает».
Геометрический тест оставлен запасным, на случай если netIdentity ещё не
привязан в первые кадры матча.

Попутно: массив кандидатов был на 8 элементов при 12-13 игроках в списке —
свой PM мог оказаться девятым и не рассматривался. Расширен до 16, флаг
ищется по всему списку до фильтрации.

## Геометрия ESP

Позиция берётся не из серверного тика, а из того, что игра рисует:

| Что | Откуда |
|---|---|
| Голова | `KCC.head` (0x88), интерполированный Transform |
| Ноги | `KCC.Motor(0x68).LastInterpolatedPosition` (0x1EC) |
| Живая высота | `Motor.CapsuleHeight` (0x34) — читаемый признак приседа |
| Скорость | `Motor.BaseVelocity` (0x210) |

`PM.kccReference` (0xB0) — это `InterfaceReference<sA>`, обёртка. Смещение
`_component` внутри неё не угадывается: перебираются первые 0x40 байт и
берётся кандидат, у которого `KCC.player` (0x78) указывает обратно на
исходный PM.

## W2S через матрицу движка

`RaycastManager.m_WorldCamera (0x30) -> Camera -> m_CachedPtr (0x10) -> нативный объект`

Смещения матриц зависят от версии Unity и живут в libunity.so, поэтому ищутся
по подписи в окне 0x600:

- **view** — последняя строка (0,0,0,1), базисные столбцы единичные и взаимно
  перпендикулярны, трансляция ненулевая
- **proj** — `m23 == -1`, `m33 == 0`, диагональ в 0.15..12

Позиция камеры извлекается из самой матрицы: `eye = -Rᵀ·t`. Углы аимбота
обязаны считаться от той же точки, из которой строится проекция — иначе
прицел уезжает по вертикали.

Когда живого источника проекции нет, ESP **не рисуется вообще**. Раньше в этом
случае подставлялись экранные координаты прошлого кадра: они статичны, и боксы
ехали вместе с поворотом экрана.

## Интерфейс

Отдельный модуль `src/ui_v3.cpp`, размеры выведены из физики устройства:

```
2400x1080, ~6.7", 395 ppi  ->  1 мм = 15.5 px
палец: минимум 7 мм, комфорт 9 мм, подушечка большого 11 мм
дуга большого пальца 75 мм -> центр экрана в ландшафте достаётся
                              только указательным
```

Высота панели ВЫВЕДЕНА из строки, а не задана процентом: шапка 8 мм + ровно
5 строк по 8 мм. При произвольном проценте снизу остаётся мёртвая полоса.
Контролы в две колонки — по горизонтали места вдвое больше нужного.

**Стекло** собирается слоями: ореол, подложка, свет сверху, анимированный арт,
цветная дымка, зерно, кромка преломления. Все цветные слои читают один акцент.

Два подводных камня ImGui, из-за которых углы выглядели обрезанными:

1. `AddRectFilledMultiColor` **не принимает радиус** — всегда рисует острый
   прямоугольник. Градиенты теперь красятся по вершинам скруглённого пути.
2. Окно клипует drawlist по своим границам, и ореол обрезался ровно по краю
   панели. Окна расширены на 3.6 мм во все стороны.

## Что не работает и почему

| Функция | Причина |
|---|---|
| Валл-чек | `BuildingPiece.saveList` наполняется только на СЕРВЕРЕ (`OnStartServer`). Резерв через `NetworkClient.spawned` находит единицы объектов |
| Скрытие тимейтов | Все три источника состава пусты: `nWc.team` = 0, `TeammateStates` пуст, UI-панель тоже |
| Скелет | `KCC.head` отдаёт указатель, но трансформ из него не читается |

Соответствующие тогглы убраны из меню, функции выключены — чтобы не тратить
чтения на заведомо пустые цепочки.
