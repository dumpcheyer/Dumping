Обновлён 2026-07-25 11:30. Собран NDK r26d, проверен на устройстве.

## Восстановление Font.h

`include/ImGui/font/Font.h` весит 6.89 МБ и не проходит через GitHub Contents API
(лимит 4 МБ на тело запроса). Лежит рядом как `Font.h.gz.b64`.

```bash
cd include/ImGui/font
base64 -d Font.h.gz.b64 | gunzip > Font.h
md5sum Font.h   # 7c667be5b679273f9f4a0424c75d7261
rm Font.h.gz.b64
```

Без этого шага сборка упадёт на отсутствующем `OPPOSans_H`.

## Сборка

```bash
ndk-build -j8 \
  NDK_PROJECT_PATH=$(pwd) \
  APP_BUILD_SCRIPT=$(pwd)/Android.mk \
  NDK_APPLICATION_MK=$(pwd)/Application.mk
```

Результат: `libs/arm64-v8a/eclipsoxide` (~3.65 МБ), standalone PIE, под `su`.

Если распаковывали NDK через `unzip` или Python `zipfile` — симлинки в тулчейне
превращаются в текстовые файлы и `clang` не находится. Восстанавливать по флагу
`S_ISLNK` в `external_attr`.

## Что изменилось с прошлого снапшота

### ESP больше не строится на серверном тике

Раньше позиция бралась из `PM.lastTickPosition` (0x1C8) — это серверный тик
10-20 Гц, поэтому бокс отставал от бегущей цели, и вертикальную привязку
приходилось подбирать руками (`espBoxYOffset = -1.84`).

Теперь якоря берутся из того, что игра реально рисует:

| Что | Откуда |
|---|---|
| Голова | `KCC.head` (0x88), интерполированный Transform |
| Ноги | `KCC.Motor(0x68).LastInterpolatedPosition` (0x1EC) |
| Живая высота | `Motor.CapsuleHeight` (0x34) |
| Скорость | `Motor.BaseVelocity` (0x210) |

`PM.kccReference` (0xB0) — это `InterfaceReference<sA>`, обёртка, а не сам KCC.
Смещение `_component` внутри неё не угадывается: вместо этого перебираются
первые 0x40 байт и берётся кандидат, у которого `KCC.player` (0x78) указывает
**обратно на исходный PM**. Случайным такое совпадение быть не может.

Фолбэк, когда кость головы не отдаёт матрицу: точка глаз считается
геометрически как `interpPos.y + CapsuleHeight + lookHeightOffset`.

### W2S через матрицу движка

Вместо реконструкции базиса из углов `MouseLook` берутся настоящие
`worldToCameraMatrix` и `projectionMatrix`:

```
RaycastManager.m_WorldCamera (0x30) -> Camera -> m_CachedPtr (0x10) -> нативный объект
```

Смещения матриц внутри нативного объекта зависят от версии Unity и живут в
libunity.so, поэтому ищутся по подписи в окне 0x600 с шагом 4:

- **view** — последняя строка ровно (0,0,0,1), три базисных столбца единичной
  длины и взаимно перпендикулярны, трансляция ненулевая
- **proj** — `m23 == -1`, `m33 == 0`, диагональ в 0.15..12, восемь позиций строго нулевые

Поиск один раз за сессию (~256 точечных чтений одного объекта), результат
кэшируется по указателю нативной камеры. На замеренном устройстве нашлись на
`view @+0x70`, `proj @+0xB0`.

Через матрицу идут все пути отрисовки — бокс, скелет, 3D-бокс и точка
прицеливания. Если хотя бы один остался бы на углах, он разъехался бы с остальными.

### Позиция камеры для аимбота

Углы доворота обязаны считаться от той же точки, из которой строится проекция.
Раньше проекция шла через матрицу, а углы — от `worldCameraRoot`; разница
между этими точками и давала «прицел выше цели».

Для ортонормированной `V = [R | t]`, где `t = -R·eye`, обратно `eye = -Rᵀ·t`.

### Присед

Ранее считался нечитаемым — искался бит в `PlayerFlags`, которого там нет.
Признак оказался геометрическим: игра уменьшает `Motor.CapsuleHeight` при
приседании. Точка прицела строится как доля от живой высоты `head.y - feet.y`,
поэтому присед отрабатывается сам:

```
head 0.97   neck 0.86   body 0.68
```

### Смерть и респавн

Старый детектор ловил замороженные углы `MouseLook`, но в режиме наблюдателя
углы продолжают меняться — и он молчал. При этом `g_localPlayer` ещё указывает
на PM трупа, и матрица читается из камеры трупа.

Теперь смерть определяется прямо (`PM.respawning` 0x208 + HP<=0), а смена PM
или указателя камеры немедленно сбрасывает кэш матрицы. Гистерезис против
мигания (8 промахов) на смену владельца не распространяется — иначе он же и
удерживал бы протухшую матрицу.

### Команда

`nWc.team` (0x90) в этом билде приходит нулём даже когда игрок в команде,
поэтому проверка через `pf` молча ничего не скрывала. Состав лежит в
`nWc.TeammateStates` (0x70) — `Dictionary<string userID, TeammateStatus>`,
ключи сверяются с `PM.userID` (0x278) цели.

## Диагностика в логе

| Маркер | Что показывает |
|---|---|
| `[w2s]` | активна ли матрица, найденные смещения, сколько целей с якорями |
| `[cammat]` | где именно нашлись view/proj при первом заходе |
| `[anchor]` | цепочка до KCC по шагам, если якоря не поднялись |
| `[aim]` | `eyeSrc=M` матрица / `=R` реконструкция, точка и углы |
| `[team]` | состояние словаря сокомандников и его ключи |
| `[respawn]` | смена локального PM и сброс кэша камеры |

`stage` в `[anchor]`: 1 нет ссылки, 2 не нашли KCC, 3 не читается голова,
4 нет позиции ног, 5 геометрия не прошла санити.

## Открыто

  получает постройки от сервера, а не проблема layout'а HashSet

## Оффсеты

Все в `include/oxide_offsets.h`, актуальны для сборки игры от 2026-07-24.
Классы резолвятся через `s_TypeInfoDefinitionTable[TDI]`, не через захардкоженные
TypeInfo RVA — переживает мелкие обновления.
